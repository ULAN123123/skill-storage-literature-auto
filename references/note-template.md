# 子笔记模板（Paper Card）

Zotero 笔记只接受 **HTML**，不接受 Markdown。Zotero 会按自己的 schema 解析并消毒 HTML：**只保留语义标签与少数结构化属性**（`h1 h2 h3 h4 h5 h6 p ul ol li blockquote strong em code sub sup table tr td th hr`），以及：

- `<span class="math">$…$</span>` / `<pre class="math">$$…$$</pre>`（公式节点，KaTeX 渲染，可编辑）
- `span style="color: …"`（转成文字颜色标记，可用于把来源标注变灰）

其余 `style`、自定义 `class`、`script`、`iframe` 一律丢弃。**公式靠的不只是"写 LaTeX"，而是必须落成上面两种 math 节点**，否则 `$…$` 会原样显示。

## 结构

内容结构 **必须以 `summary-prompt.md` 的提示词原文为准**：输出完整的 **01–16 节 Paper Card**，节标题、顺序与取舍以提示词要求及论文实际内容为准，不得改写成笼统摘要或只翻译摘要。

以下为 HTML 技术骨架示例，节标题为建议映射（最终以提示词与论文实际内容为准）：

```html
<h1>Paper Card · {标题}</h1>

<p><strong>题录</strong>：{作者}（{年份}）· {期刊/来源}</p>
<p><strong>处理信息</strong>：全文 {字符数} 字符；{若截断：结论仅基于前 N 字符}</p>

<h2>01. 一句话结论</h2>
<p>{解决什么问题、采用什么方法、得到什么有边界的结果}</p>

<h2>02. 研究问题</h2>
<p>{具体研究问题，以及现有方法为什么不能充分解决}</p>

<h2>03. 问题—局限—思路—设计—验证—结论的逻辑链</h2>

<h2>04. 方法总体流程</h2>
<p>{通俗解释输入、输出与主要模块}</p>

<h2>05. 核心模块与作用</h2>
<p>{每个模块的作用、为什么需要、去掉后的影响}</p>

<h2>06. 关键公式与符号</h2>
<p>{仅保留必需公式；解释每个符号、公式作用与直观含义。行内用 <code>$…$</code>，行间用独立成段的 <code>$$…$$</code>}</p>

<h2>07. 实验—验证主张—对比对象—关键结果—支持结论 证据表</h2>

<h2>08. 关键结果</h2>

<h2>09. 结论边界</h2>

<h2>10. 作者声称 vs 实验直接支持 vs 不能推出</h2>

<h2>11. 作者明确承认的局限性</h2>

<h2>12. 可迁移的方法与实验设计</h2>

<h2>13. 可验证的研究方向</h2>

<h2>14. 来源标注核对</h2>
<p>{重要数字、方法判断、结论对应的章节/图/表/公式/PDF 页码}</p>

<h2>15. 分析范围说明</h2>

<h2>16. 总体评价</h2>

<blockquote>来源：{期刊/DOI/arXiv}；本笔记由 {模型} 基于 PDF 全文生成，数值请以原文为准。</blockquote>
```

## 写作规则

1. **只用原文有的东西**。数值、样本量、结论方向必须能在 `text` 中找到；找不到写"原文未报告"。
2. **区分事实与推断**。推断句以"可能/推测"开头，不与原文结论混写。
3. **逐项标注来源**。所有重要数字、方法判断和结论必须注明来自论文的具体章节、图、表、公式或 PDF 页码；无法从论文中得到的数字、结论和方法不得填写。
4. **截断标注**。`truncated: true` 时必须在“分析范围说明”节写明截断位置，并在“关键结果”“结论边界”节避免绝对化表述。
5. **区分三类结论**。作者声称的结论、实验直接支持的结论、不能从当前证据推出的更强结论，必须分开表述。
6. **局限单列**。仅整理作者明确承认的局限性，不得与分析者的批评混在一起。
7. **无正文时**。`text` 为空：只输出 `<h1>`、题录、`<p>无法提取正文（可能为扫描件，需 OCR）</p>`，不生成 01–16 节。
8. **长度**。默认 600–1200 字；用户指定字数时以用户为准。
9. **语言**。跟随用户；未指定时用中文，专有名词保留英文原文。
10. **不要写"本文非常重要/填补空白"这类空话**，用可核对的具体信息替代。
11. **表格数字的落地前提**：≥6 列、或一行出现连续多个数值的表，必须先看 `rendered-pages` 页面图确认列归属再写；列归属无法确认的数字不写，改写"原文未报告/列对应关系无法确认"。跨表引用同一指标要注明口径（全量主表 vs 抽样子集）。
12. **正文来源要声明**：`处理信息` 行需写明全文来自哪里——`Zotero 全文索引` 还是 `PDF 抽取（prepare_paper.py，PDF p.X–Y）`。后者属于偏差，必须在「分析范围说明」节复述一次。
13. **公式与符号按下面的固定写法**，转换器才能稳定落成 math 节点。

## 公式与上下标规范（B 阶段硬性写法）

| 场景 | 正确写法 | 转换后的笔记 HTML |
| --- | --- | --- |
| 行内公式 | `$I_V$`、`$D_T = LLM_T(q,R,M_R)$` | `<span class="math">$…$</span>` |
| 行间公式（独占一段） | `$$` 单独一行包裹 | `<pre class="math">$$…$$</pre>` |
| 单个符号下标 | `$I_V$` 或 `I_{V}` | math 节点 / `<sub>` |
| 组合上下标 | `$r^{(t)}_{c}$` | math 节点 |
| 集合、运算符 | `$I_{T\V}$`、`$\cup$`、`$∈$` 可直接写 `∈ ∪ ∩` | math 节点 |
| 数字幂次 | `$10^6$` | math 节点 |

禁止：

1. **标题（h1–h6）里放公式**：Zotero 的标题内容模型不允许 `math_inline`，写了会被丢掉。标题只写纯文字。
2. **裸写下标**如 `I_V`、`D*_q`、`t=1…T` 之外的 `X_y`：在 Markdown 里 `_` 是强调符号，容易被吃成斜体；要么整体进 `$…$`，要么写 `X_{y}`。
3. **用 `*` 表示星号**：`A*` 会被 Markdown 当强调起点，写 `$A^{*}$`。
4. **KaTeX 不支持的写法**：`\begin{equation}`、`\label`、`\cite`、`\bm`、`\usepackage`。多行公式用 `\begin{aligned}…\end{aligned}` 且整段包在 `$$` 内。
5. **公式放进 `<code>`**：会被当源码原样显示，不渲染。

转换器（`scripts/make_notes_json_v2.py`）对历史写法有兼容：`$…$`、`\(…\)`、`X_y`、`X_{y}`、`X^{y}`、`X^{(t)}_{c}` 都能转，但**规范写法解析率最高、不会误判**；`I*{T\V}` 这类被 Markdown 啃坏的原文只能尽力还原，语义需回原文核对。
